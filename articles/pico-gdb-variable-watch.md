単にGDBのコマンドを紹介するのではなく、実際のプログラムを題材に、何を確認したいのか、そのためにどう操作すればよいのかを考えながら進めます。

# 今回のデバッグテーマ

## 初期タスクは正常に生成されたのか？

Try Kernelの起動処理では、初期タスクを生成し、そのタスクを実行します。

書籍P.74の`kernel/inittsk.c`には、次の処理があります。

```c
ID tskid_ini;
```

```c
tskid_ini = tk_cre_tsk(&ctsk_ini);  // 初期タスク生成
tk_sta_tsk(tskid_ini, 0);           // 初期タスク実行
```

`tk_cre_tsk()`はタスクを生成するAPIで、その戻り値が`tskid_ini`に保存されます。

仮に、Try Kernelを起動しても初期タスクが動かなかったとします。

原因はいろいろ考えられますが、まずはタスク生成が正常に行われたかを確認したいところです。

そこで、今回は`tskid_ini`という変数に注目します。

## 今回確認したいこと

- **① `tskid_ini`の値は何か？**  
  タスク生成APIの戻り値を確認し、正常に生成されたかを判断する。

- **② `tskid_ini`の値はいつ変わるのか？**  
  タスク生成処理の前後で変数の値を比較する。

- **③ プログラムを動かしながら変数を監視できるか？**  
  ステップ実行やブレークポイントを使い、値の変化を追いかける。

- **④ 変数が書き換わった瞬間に停止できるか？**  
  ウォッチポイントを使い、変数の変更を検出する。

- **⑤ 変数の値はメモリ上でどう見えるのか？**  
  変数のアドレスを調べ、メモリに格納されたデータを確認する。

この5つを、GDBで実際に調べてみます。
